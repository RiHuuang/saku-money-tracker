## Historical bounded design proposal

1. Keep the 10 MB logical snapshot ceiling. The deployed versioned endpoint streams one bounded JSON document to R2 and uses a D1 compare-and-swap on the existing revision; a conflict deletes the staged object. The browser validates the ledger before upload, and the Worker enforces the byte limit, version header, and exact stored length. Repeat maximum-size runs and add any further validation needed before release. Imported gzip backups remain readable through streamed client-side decompression, preserving historical objects.
2. Stream downloads from R2 to the client. Avoid full-document parse, gzip, and serialization inside one Worker invocation. Preserve the existing user identity, session, and revision semantics. Updated Android foreground, widget, and browser clients must use the same protocol and URL; old builds continue on GCP only until the coordinated cutover.
3. The current mirror pins the baseline and target snapshot in D1, computes bounded changes in the client, expands only required Sheet grid rows, compares each affected range to its previous app-generated values, and writes only an exact matching range. A 409 stops on manual edits; a Google outage leaves the backup committed and `sheetPending=true`. The client retries quota 429 responses with backoff and paces batches to about 50 per minute, below [Google's 60-read and 60-write requests per minute per user quota](https://developers.google.com/workspace/sheets/api/limits). The 92,000-row Sheet passed. Isolate the 10.988 ms invocation and verify interrupted-job resumption across process restart before cutover.
4. Separate basic Google sign-in from optional Drive consent. A user who withholds Drive access must still enter the app, see a clear pending mirror state, and be able to grant Drive later. Keep Android's bearer interface and browser's cookie/CSRF interface.
5. Deploy the bounded version and measure cold login, refresh, avatar, representative sync, 9.98 MB sync, and full-sheet mirror with Cloudflare invocation metrics and a real Google account. Require all to pass on Workers Free. Then register the callback, confirm public OAuth with an account outside the test-user list, validate both Android and browser sign-in, and only then perform the brief GCP write freeze and final re-export/import.

The current Worker and web app remain a read-only migration preview while public login is disabled. The old Cloud Run URL remains in `.env.production`, and the old service still accepts writes; no production cutover has occurred.
