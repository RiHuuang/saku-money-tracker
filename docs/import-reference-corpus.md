# Indonesian import reference corpus

Research checked 2026-10-15. These are public provider guides, **not** customer statements or copied banking screenshots. They establish available surfaces and edge cases; actual column layouts and current app pixels still need consented, redacted examples. Keep all test inputs synthetic and do not commit real account numbers, names, balances, or transaction IDs.

The implemented tests cover the 30-row batch, transfer accounting, card mapping, QRIS correction, pending rejection, direction conflicts, and existing BCA PDF parsing. The October 15 Gemma 4 staging benchmark returned all 30 fabricated rows with exact date, whole-rupiah amount, direction, normalized merchant name, and activity matches; it does not establish accuracy on real provider layouts. Local browser checks covered mixed text/image routing and a fabricated AES-256 encrypted text PDF: missing and wrong passwords failed, while the correct password yielded its transaction text. The Catch Up UI password prompt also led to a one-row review through a locally intercepted extraction response. Provider-specific exact formats remain open.

On 2026-10-15, the Catch Up file input was checked on a physical Android 24129PN74G using an isolated `id.saku.money.stage` APK. Android's native file chooser opened; selecting `output/synthetic-wallet-history.png` from local Downloads added one image source to the on-device draft and displayed its account selector. Extraction and transaction saving were not run. The synthetic draft and device file were removed, the normal stage APK was restored, and `id.saku.money` remained installed throughout. This verifies native selection and local draft creation on that device, not provider-specific AI accuracy or authenticated end-to-end import.

Because screenshots can omit rows outside the viewport, absence from a screenshot must never trigger a deletion suggestion. Users must review imported rows against the original, and uncertain rows stay in the local draft.
